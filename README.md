# Moodle AI Assistant

Локальний REST API на FastAPI з інтеграцією OpenAI API та Chrome-розширенням
із Side Panel і плаваючою Moodle-панеллю. Для локальної перевірки є тестова
HTML-сторінка, що імітує кілька
типів питань. Також перевірено збережену HTML-копію сторінки перегляду спроби
Moodle; живу інтеграцію потрібно перевірити вручну. Автоматичне
вибирання чи надсилання відповідей відсутнє. Docker і серверне розгортання поки
не входять до проєкту. Додано Windows Tkinter Launcher, локальну SQLite-статистику
токенів і точний локальний кеш відповідей за текстом питання.

## Вимоги

- Python 3.13
- API-ключ OpenAI та доступна для цього API-проєкту модель, що підтримує
  Responses API і Structured Outputs

## Встановлення у Windows PowerShell

```powershell
cd backend
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Якщо PowerShell забороняє активацію середовища, дозволь її лише для поточного
вікна й повтори команду активації:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process
.\.venv\Scripts\Activate.ps1
```

## Налаштування OpenAI

Повернись у корінь репозиторію та створи локальний `.env` з шаблону:

```powershell
cd ..
Copy-Item .env.example .env
notepad .env
```

Заповни `OPENAI_API_KEY` власним API-ключем і `OPENAI_MODEL` точним ідентифікатором
моделі. Не додавай реальний `.env` до Git. Він уже виключений у `.gitignore`.
Для локального запуску API потрібен саме API-ключ OpenAI; підписка ChatGPT не є
заміною API-доступу. Створи ключ у [налаштуваннях API-ключів OpenAI](https://platform.openai.com/api-keys).

Не задавай модель навмання. Доступність залежить від API-проєкту й дозволів
облікового запису. Переглянь доступні ідентифікатори через [список моделей API](https://developers.openai.com/api/reference/resources/models/methods/list)
або `client.models.list()`, потім перевір у документації моделі підтримку
Responses API та Structured Outputs.

## Запуск сервера

З папки `backend` та з активованим `.venv`:

```powershell
python -m uvicorn app.main:app
```

API доступне на `http://127.0.0.1:8000`. На цьому комп'ютері `--reload` спричиняв
помилку Windows watcher; для звичайної роботи він не потрібен. За бажанням
можна спробувати перезапуск зі стеженням лише за папкою застосунку:

```powershell
python -m uvicorn app.main:app --reload --reload-dir app
```

## Windows Launcher

Launcher керує тим самим FastAPI backend. Після встановлення залежностей запусти
його з папки `backend`:

```powershell
cd backend
.\.venv\Scripts\python.exe launcher.py
```

Кнопки **Start Assistant**, **Check Status** і **Stop Assistant** керують backend
на `http://127.0.0.1:8000`. Launcher перевіряє `/health` перед запуском, щоб не
створювати дубль. Якщо сервер уже працює окремо, Launcher повідомить про це, але
не завершуватиме його. Закриття Launcher зупиняє тільки backend-процес, який
запустив саме Launcher. Для ярлика на Робочому столі створи ярлик на
`Start Moodle AI Assistant.bat` у корені проєкту.

## Використання токенів і витрати

Після успішної відповіді OpenAI backend зберігає повернуті API usage-значення
(`input_tokens`, `output_tokens`, `total_tokens`) і модель. Відповіді без usage
метаданих не створюють нульових записів. Тексти питань, промпти, API-ключі та
повні відповіді в статистику не потрапляють. Однаковий OpenAI response ID
рахується лише один раз.

SQLite-файл за замовчуванням зберігається в
`%LOCALAPPDATA%\MoodleAIAssistant\usage.sqlite3`. Він містить статистику токенів,
таблицю кешу питань і окремі таблиці імпортованих результатів тестів. Можна
задати іншу теку через `MOODLE_ASSISTANT_DATA_DIR`.
Кеш зберігає оригінальний текст питання та відповідь локально в профілі Windows;
не зберігає API-ключ і не надсилає питання в статистику. Поточна сесія — час
роботи поточного процесу backend; all-time охоплює записи токенів у базі.
Launcher читає тільки агрегати з локального `GET /api/usage`.

## Імпорт результатів завершеного тесту

На сторінці перегляду спроби Moodle плаваюча панель показує кнопку
**Зберегти статистику**. Вона читає видимі питання, варіанти, відмічені відповіді,
оцінки та доступний Moodle feedback і надсилає ці структуровані дані на локальний
`POST /api/quiz-import`. HTML і вбудовані скрипти не надсилаються та не виконуються.
Звичайна активна спроба не показує цю кнопку.

Дані результатів зберігаються окремо від AI-відповідей і токен-статистики.
Класифікація використовує точні десяткові числа: `incorrect` означає, що вся
збережена комбінація виборів отримала 0 балів; `full` — максимум для цього питання;
`partial` — проміжний результат; `unknown` — оцінки відсутні або суперечливі.
Повний бал підтверджує лише зафіксований вибір у цій спробі. Сховище не робить
висновків про глобально правильний варіант. Дані імпорту читаються backend-ом
лише для точного збігу питання й набору варіантів; модель отримує їх тільки коли
потрібна нова генерація.

Після того як ти зберіг завершену спробу, під час читання питань на Moodle
панель перевіряє локальну історію. Якщо Moodle раніше дав питанню 0 балів,
картка підсвічується червоним. Для питання з одним radio-вибором і незмінним
набором варіантів панель також пропонує **Спробувати без відомого неправильного
варіанта**. Backend перевіряє імпортовані результати і для звичайної генерації,
і для цієї окремої дії. Якщо кешована відповідь збігається з відхиленим варіантом,
вона не повертається: запускається AI з поточними варіантами та даними Moodle.
Якщо модель один раз повторить відхилений radio-вибір, backend зробить рівно одну
додаткову спробу; якщо конфлікт залишиться, клієнт отримає контрольовану помилку.
Відповідь із таким контекстом не записується у звичайний кеш.

Для checkbox нульова оцінка описує всю збережену комбінацію, а не кожен пункт
окремо: картка попереджає про минулу помилку, і backend передає невдалу
комбінацію моделі, але не блокує кожен checkbox-варіант окремо.
Старі імпортовані записи без збереженого типу input безпечно показують
попередження; щоб увімкнути зіставлення radio-варіанта, повторно натисни
**Зберегти статистику** на тій самій сторінці результату. Дубльований імпорт
лише доповнить відсутній тип input і не змінить оцінку чи вибір.

Імпорт є ідемпотентним за Moodle attempt ID і course module ID з URL. Інша спроба
з іншим ID зберігається окремо, навіть коли питання ті самі. Якщо сторінка не має
ні attempt ID, ні usage ID, повторні натискання дедуплікуються лише в межах
поточного завантаження сторінки; після повторного відкриття така сторінка може
бути імпортована ще раз.

База містить текст питань, варіанти та вибір з завершеної спроби у локальному
профілі користувача. Це навчальні дані, а не анонімна статистика. Вони не
включаються до `/api/usage` і не змінюють AI-кеш. Резервні копії чи очищення бази
потрібно робити вручну.

## Локальний кеш відповідей

Перед кожним викликом OpenAI backend шукає точний запис за нормалізованим текстом
питання. Нормалізація застосовує Unicode NFC, згортає послідовності пробілів і
переносів рядка в один пробіл, прибирає крайні пробіли та порівнює без урахування
регістру. Пунктуація та слова зберігаються. Варіанти відповіді не входять до ключа;
не використовується нечіткий пошук.

Новий результат зберігається як `unverified` і надалі може бути повторно
використаний. Для питань із варіантами збережена відповідь використовується лише,
якщо її текст точно й однозначно присутній у поточному списку. Якщо список
змінився так, що відповідь не можна безпечно зіставити, backend звернеться до AI.
Кеш-хіт збільшує лічильник використань запису, але не викликає OpenAI та не додає
токени до статистики.

У запиті можна передати `"force_refresh": true`, щоб пропустити lookup і явно
отримати свіжу відповідь від OpenAI. За замовчуванням значення `false`, тому старі
клієнти без цього поля продовжують працювати у режимі cache-first. Відповідь містить
поле `source`: `cache` або `ai`; розширення показує джерело біля результату.

Примусове оновлення нового питання створює запис `unverified`. Якщо запис
`unverified` уже є, нова відповідь замінює його, а попередня й нова версії
записуються в таблицю `question_cache_refreshes` в одній транзакції. `verified` і
`rejected` записи не замінюються й не реактивуються: свіжу відповідь повертаємо
лише поточному запиту, але не записуємо поверх такого запису. Щоб дозволити заміну
перевіреного запису, спершу вручну зміни його статус на `unverified`, а тоді
натисни fresh-response кнопку. Відхилений запис залишається `rejected`, доки статус
не змінено вручну.

Записи можна переглянути чи позначити вручну з папки `backend`:

```powershell
python manage_question_cache.py list
python manage_question_cache.py status 3 verified
python manage_question_cache.py status 3 rejected
python manage_question_cache.py status 3 unverified
```

`rejected` виключає запис із повторного використання; запити йдуть до AI, але не
реактивують його автоматично. Запис зі статусом `verified` не перезаписується
автоматично. Змінюй статус лише після перевірки відповіді. Файл кешу виключений з
Git разом із SQLite-файлами.

Модель береться з `OPENAI_MODEL`; поточне локальне значення — `gpt-6-luna`.
Ціни задаються у [backend/pricing.json](backend/pricing.json) у USD за мільйон
токенів. Для `gpt-6-luna` додано стандартні ціни: $0.10 за мільйон вхідних,
$0.01 за мільйон кешованих вхідних і $0.50 за мільйон вихідних токенів за
[офіційною сторінкою цін OpenAI](https://developers.openai.com/api/docs/pricing),
перевірено 2026-10-21. Кешовані токени вже включені в input count і не додаються
до нього вдруге. Для невідомої моделі вартість буде `Unknown`. Це оцінка за
таблицею, не рахунок OpenAI; зміни ціни впливають на нові записи, старі зберігають
оцінку на момент запиту.

## Кнопка розширення у Chrome

Після Reload розширення натискання його іконки на Moodle або локальній тестовій
сторінці показує чи ховає плаваючу панель. Повторні натискання не створюють
дублікатів. На непідтримуваній сторінці з'явиться значок `!`; якщо скрипт сторінки
ще не готовий, онови її та повтори натискання.

## Перевірка через Swagger UI

Відкрий [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs), розгорни
`POST /api/answer`, натисни **Try it out** і надішли, наприклад:

```json
{
  "question": "Яка столиця Франції?",
  "options": ["Париж", "Рим"]
}
```

Для відкритого питання поле `options` можна пропустити або передати як `[]`.
Модель має повертати `suggested_answer`, `explanation`, `confidence` і
`needs_more_context`. `confidence` — приблизна самооцінка моделі, не виміряна
ймовірність. `answer` і `message` залишені для сумісності зі старими клієнтами.

запиту використовуй Swagger UI, коли `.env` налаштований.

## Типові помилки конфігурації

- `503`: відсутній `OPENAI_API_KEY` або `OPENAI_MODEL`, або модель недоступна чи
  не підтримує потрібний формат. Перевір `.env`, ідентифікатор моделі та доступи.
- `503`: OpenAI відхилив API-ключ. Перевір, що ключ належить потрібному API-проєкту.
- `429`: перевищено ліміт запитів або квоту провайдера; повтори пізніше та
  перевір ліміти/білінг API-проєкту.
- `504`: таймаут відповіді AI-провайдера.
- `502`: мережева помилка провайдера або непридатна структурована відповідь.
- `422`: FastAPI відхилив некоректний запит до AI-виклику.

Помилки API не повертають ключ, traceback або вміст запиту. Секрети й `.env`
не записуються в код, журнали чи тести.
