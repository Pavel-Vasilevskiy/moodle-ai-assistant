# Moodle AI Assistant — Chrome extension

Розширення Manifest V3 має бічну панель Chrome і плаваючу панель, яку content
script показує на підтримуваних сторінках Moodle та локальній quiz-сторінці. Вона
зчитує питання та варіанти, а після явного натискання **Отримати відповідь AI**
надсилає вибране питання в наявний backend. Кнопка **Запросити свіжу відповідь
від AI** пропускає локальний кеш; звичайна кнопка спочатку використовує кеш.
На сторінці перегляду завершеної спроби панель також пропонує зберегти її
статистику локально. Розширення не читає Moodle-облікові дані й не вибирає або
надсилає відповіді у Moodle.

Тестова сторінка імітує лише невеликий піднабір розмітки Moodle (`.que`, `.qtext`,
`.answer`). Зчитувач бере текст варіанта зі звичайного `<label>` або з елемента,
на який вказує `aria-labelledby` (такий формат є у наданому HTML-зразку). Це
навчальний fixture, а не гарантія сумісності з усіма сторінками реального сайту.
Для `https://distance.kuk.edu.ua` додано окремий точний дозвіл. Скрипт читає DOM
того документа Moodle, в якому він запущений; вкладені cross-origin iframe тут не
охоплюються.

Потрібен Chrome 114 або новіший, оскільки розширення використовує Side Panel API.
Додаткові залежності чи збирач JavaScript не потрібні.

## Запуск локально

1. Налаштуй backend за інструкціями в [backend README](../backend/README.md) та
   запусти його з папки `backend` у першому вікні PowerShell:

   ```powershell
   python -m uvicorn app.main:app
   ```

2. Перевір, що `http://127.0.0.1:8000/health` відповідає успішним статусом.
3. У другому вікні PowerShell, з кореня репозиторію, запусти локальний сервер:

   ```powershell
   py -3 -m http.server 8765 --bind 127.0.0.1 --directory extension
   ```

   Відкрий `http://127.0.0.1:8765/test-launcher.html` у звичайному вікні.
   Натисни **Open test quiz popup**. Launcher використовує `window.open()` з
   ознакою `popup` та запитуваним розміром 980×760. Chrome може ігнорувати частину
   візуальних параметрів або заблокувати popup; у такому разі дозволь popup для
   локальної тестової сторінки й повтори дію. Сам quiz — той самий
   `test-page.html`, з radio-, checkbox- та відкритим текстовим питаннями.
4. У Chrome відкрий `chrome://extensions`, увімкни **Developer mode** і натисни
   **Load unpacked**. Вибери папку `extension` цього репозиторію. Після змін у
   файлах натисни **Reload** на картці розширення й онови тестову сторінку.
5. У launcher-вкладці натисни **Open test quiz popup**. У popup-вікні праворуч
   унизу тестової сторінки має з'явитися кнопка **Відкрити Moodle AI Assistant**.
   Натисни її: плаваюча панель відкриється поверх quiz-сторінки й не потребує
   Chrome Side Panel.
6. Натисни **Зчитати запитання**. Панель має показати три питання та текст
   варіантів для radio і checkbox. Для відкритого питання буде повідомлення, що
   воно без варіантів відповіді. Якщо деякі блоки не підтримуються, відобразиться
   їхня кількість. Натисни **Отримати відповідь AI** під потрібним питанням.
   Для звичайного запиту backend спершу перевіряє кеш. Кнопка **Запросити свіжу
   відповідь від AI** явно обходить кеш і виконує новий AI-запит. Під результатом
   буде вказано джерело: кеш або новий AI-запит. Кожне питання аналізується окремо
   після явного натискання; зчитування не надсилає запит і не вибирає відповідь.
7. Клацни іконку Moodle AI Assistant на панелі інструментів Chrome: плаваюча
   панель має сховатися; повторне клацання повертає її без створення дубліката.
   Також перевір згортання/розгортання, закриття та повторне відкриття з самої
   панелі. Жодна з цих дій не закриває quiz-вікно.
8. Переконайся, що backend працює на `http://127.0.0.1:8000`. Відповідь,
   пояснення, приблизна впевненість і повідомлення про недостатній контекст
   мають з'явитися прямо під питанням у popup. AI не гарантує правильність;
   перевіряй пояснення перед використанням відповіді. Якщо backend не запущений,
   отримано помилку конфігурації або вичерпано ліміт API, панель покаже помилку.

Backend URL налаштований в `host_permissions` файлу `manifest.json`; панель бере
звідти адресу й додає `/api/answer`. Доступи content script обмежені локальною
тестовою сторінкою та `https://distance.kuk.edu.ua/*`; доступу до інших сайтів
немає. Після зміни manifest перезавантаж розширення та онови Moodle. Не додавай
у розширення OpenAI API key.

## Підготовка до перевірки справжнього DOM

1. Відкрий `chrome://extensions`, натисни **Reload** для Moodle AI Assistant.
   Якщо Chrome запитає доступ до `distance.kuk.edu.ua`, дозволь його для цього
   сайту. Content script наразі запускається лише у верхньому документі.
2. Відкрий тест і popup Moodle. Зафіксуй адресу popup з адресного рядка. Якщо
   плаваюча панель з'явилася, натисни **Зчитати запитання**; якщо ні або питання
   не знайдені, це теж корисний результат для діагностики.
3. У popup відкрий DevTools (`F12`), вибери інструмент-піпетку (**Ctrl+Shift+C**)
   і клацни текст питання. На вкладці **Elements** знайди найближчий контейнер
   питання, що містить текст і варіанти, потім вибери **Copy → Copy outerHTML**.
4. Перевір, чи питання всередині iframe: у Console виконай
   `Array.from(document.querySelectorAll("iframe"), frame => frame.src)`.
   Якщо список містить адресу iframe, перемкни Console execution context на цей
   frame і перевір `document.querySelectorAll(".que").length`. Збережи адресу
   frame разом із HTML одного контейнера питання.
5. Надішли лише URL верхнього popup, URL iframe (якщо є) та HTML одного питання.
   Прибери з фрагмента ім'я, оцінки та інші особисті дані. Не надсилай cookies,
   session tokens або паролі.

Ці кроки допоможуть перевірити DOM і межі iframe, якщо на сайті виникне проблема.

## Імпорт статистики завершеної спроби

Після завершення тесту відкрий сторінку перегляду результатів у popup-вікні.
Кнопка **Зберегти статистику** має бути доступною на завершеній спробі, але
прихованою на активному тесті та інших сторінках. Натисни її й перевір
повідомлення про імпортовану кількість. Повторне натискання має повідомити, що
спробу вже збережено, без створення дублікатів.

Автоматична перевірка використовує санітизований DOM-fixture, побудований за
наданою HTML-копією сторінки перегляду спроби. У вихідному HTML було 15 питань;
блоки мали `.que`, `.qtext`, `.answer` та `.grade`. Варіанти з'єднані з input через
`aria-labelledby`, а вибір позначений `checked`. Оцінки були у форматі
«Балів X з Y». Наданий HTML не містив явних маркерів правильності окремих
варіантів або Moodle feedback, тому ці поля залишаються невідомими, коли їх немає
в DOM. Сумісність із живою сторінкою результатів усе ще потрібно підтвердити в
Chrome; тема чи версія Moodle можуть відрізнятися.

Backend зберігає імпорт в окремих таблицях `quiz_imports` і
`quiz_import_questions` у `%LOCALAPPDATA%\MoodleAIAssistant\usage.sqlite3`.
Дедуплікація використовує attempt ID і course module ID з URL. Якщо обидва
ідентифікатори відсутні, повторні натискання дедуплікуються тільки до закриття або
перезавантаження документа.

Після збереження спроби зчитуй питання на активній Moodle-сторінці ще раз.
Картка з попередньою оцінкою 0 буде позначена червоним. Для radio-питання
з тим самим набором варіантів з'явиться дія **Спробувати без відомого
неправильного варіанта**. Backend також перевіряє історію для звичайного
запиту: якщо кеш містить цей відхилений варіант, він запускає новий AI-аналіз.
Контекстні результати не записуються у звичайний кеш. Якщо AI повторить
відхилений radio-вибір, backend зробить лише одну повторну спробу й потім покаже
контрольовану помилку. Для checkbox Moodle оцінює комбінацію відповідей, тому
комбінація передається моделі як контекст, але окремі checkbox-пункти не
виключаються.

## Перевірки

Автоматичні UI/API-контрактні перевірки написані на вбудованому Node.js test
runner, без npm та справжніх мережевих або платних запитів. З кореня репозиторію:

```powershell
node --test extension/tests/sidepanel.test.js
node --test extension/tests/content.test.js
node --test extension/tests/floating-panel.test.js
node --test extension/tests/background.test.js
node --test extension/tests/launcher.test.js
node --check extension/background.js
node --check extension/content.js
node --check extension/sidepanel.js
node --check extension/test-launcher.js
```

Також перевір backend-тести з його віртуального середовища:

```powershell
cd backend
python -m pytest
```

## Типові проблеми

- **Could not reach the backend** — backend не запущений або недоступний на
  `127.0.0.1:8000`.
- **Popup не з'явився** — браузер міг заблокувати `window.open()`; запускай його
  кнопкою на launcher-сторінці й перевір дозволи popup.
- **Read question не працює** — переконайся, що саме `test-page.html` відкрита з
  `127.0.0.1:8765`, локальний HTTP-сервер працює, розширення перезавантажене,
  а тестова сторінка оновлена після цього.
- **Плаваюча кнопка не з'явилась** — перевір точний URL popup:
  `http://127.0.0.1:8765/test-page.html`. Content script навмисно не запускається
  на launcher-сторінці або інших сайтах.
- **Відповідь AI не з'явилася** — запусти backend у теці `backend` з активованим
  `.venv`; для аналізу потрібен доступ до налаштованого AI API. Плаваюча панель
  окремо від Side Panel показує повідомлення про помилки backend/API.
- **Питання не знайдено/формат не підтримується** — поточний зчитувач очікує
  видимі блоки `.que` із `.qtext`; для реального Moodle розмітку треба перевірити.
- **Помилка доступу до backend** — перевір, що `host_permissions` містить точну
  backend-адресу, і перезавантаж розширення після зміни manifest.
- **HTTP 422** — backend відхилив вхідні дані; перевір текст питання та обмеження
  кількості/довжини варіантів.
- **HTTP 429/5xx** — помилка або ліміт backend чи AI-провайдера; прочитай безпечне
  повідомлення в панелі та журнали backend.
- **Розширення не завантажується** — відкрий його картку в `chrome://extensions`
  та переглянь повідомлення про помилку manifest/service worker.

Перевірити відповідь backend окремо можна у `http://127.0.0.1:8000/docs`.
